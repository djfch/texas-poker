三、分期路线图（串行）

严格按依赖关系排序：安全底线 → 后端重构 → 前端重写与移动端设计 → 持久化与上线设施 → 功能迭代。每期结束系统都可独立运行、可验收、可回退。

P0安全与稳定底线

不修就无法公网上线（纯后端，不碰前端）

  • 签名游客 token：创建游客时 HMAC 签发，REST 中间件 + Socket 握手双重校验，堵死身份伪造（不涉及注册体系）
  • per-room 动作串行队列 + 统一行动计时器（删 game-engine 内重复计时器），消除并发交错
  • AI 降级链修复：LLM 失败走规则引擎；isAI 改为显式布尔字段，禁改 Bot- 前缀昵称
  • 房间密码哈希存储；确认 .env 未入 git 历史并轮换 AI_API_KEY；CSP 去 unsafe-inline；生产强制 CORS_ORIGINS
  • 内存回收：周期性 cleanup 离线游客与空闲房间，游客创建接口加严格限流
  • 开局事务修复：引擎失败回滚房间状态，startGame 幂等

出口标准：无身份伪造路径；同一房间动作严格串行；长期运行内存稳定；167+ 测试全绿。

P1后端架构重构

按体量约定拆分 + 存储 DTO 化（为 PG 铺路）

  • 拆分 game-engine.js(791) / handlers.js(798)：状态机只留流程编排，socket 层按 connection/room/game/chat/scheduler 分文件，均 ≤400 行
  • 存储层 DTO 化：get 返回拷贝、写回走 update*；计时器句柄移出游戏实体（TimerService）
  • 消除跨层调用与重复逻辑（fillRoomWithAI、_isAIPlayer 各留一份；私有方法提为公开契约）
  • 清理：删领域文件内嵌 require.main 自测块；constants.js 去重 getConfig
  • 补测试：ai-rule-engine 单测、并发交错与 timeoutFold 回归测试

出口标准：存储实现可在不改调用方的前提下替换；npm test 全绿且 Linux 下不漏跑。

P2前端重写 + 移动端设计

web/ 新应用 + 以移动端为主的界面重设计

  • 新建 web/（Next.js App Router + React + TypeScript）；后端 API 与 Socket 契约不变，旧 frontend/ 保留至切换完成
  • 移动端优先：先做竖屏线框原型评审再动手；手机竖屏可完整打完一手牌（不再"请旋转屏幕"）
  • 触控操作区：大按钮 Fold/Check/Call，滑块 + 快捷筹码档位加注，防小屏误触
  • 小屏座位排布：对手紧凑卡片（头像 + 昵称 + 筹码条），自己固定底部；公共牌/底池/倒计时保证小屏可读
  • 桌面端自适应：宽屏居中牌桌，建立系统断点（手机竖屏 / 平板 / 桌面）
  • socket 封装为 React hook：自动重连、断线遮罩（重连中 第N次）、失败后手动重试
  • 状态管理用 React 内建（useReducer + Context），不引额外状态库；倒计时按服务器时钟偏移校准

出口标准：手机竖屏可完整打完一手牌且操作顺畅；新旧前端功能对等；Nginx 切流后旧 frontend/ 下线。

P3持久化与上线设施

游客档案持久化 + 可部署、可观测

  • 接入 PostgreSQL：guests(游客档案) 表起步，新增 PostgresStore 实现，存储接口不变；游客身份与筹码跨重启保留（不做战绩历史）
  • CI：GitHub Actions 跑 Node 18/20 矩阵；测试脚本改目录式调用，消除 Linux 静默漏跑
  • pino 结构化日志 + 请求 ID；/metrics 暴露在线人数/牌局数/LLM 延迟与失败率
  • Docker 加固：非 root 运行、.dockerignore、compose 资源与日志限额；Nginx 配置落仓
  • 补测试：REST 集成测试、1-2 条真实 socket.io-client E2E

出口标准：一条命令部署；重启不丢游客身份；关键指标有看板、核心链路有告警。

P4上线后功能迭代

按用户反馈排优先级

  • 排行榜（需先恢复战绩/盈亏统计，届时单独评估）
  • 观战模式、牌谱回放
  • 注册/登录/游客升级（需要时再补账号体系）
  • 锦标赛模式（多桌、升盲结构）
  • 多实例水平扩展：Redis adapter + 游戏态外置（触发条件：单实例撑不住）

原则：每一项都依赖 P3 的数据与设施基础，不提前动工。

五、决策记录（已拍板）

Q1 · 部署形态

✓ 单实例 + Nginx sticky session。Redis 化留作 P4 触发式演进（单实例撑不住时再议）。

Q2 · 持久化选型

✓ 仅 PostgreSQL，且不做战绩历史。仅承担游客档案持久化（身份/昵称/筹码跨重启保留）。

Q3 · 前端路线

✓ 仅游客，不做注册。P0 只做签名游客 token 防伪造；注册/登录/游客升级留待后期需要时再补。

✓ 串行分期：P0 → P1 → P2 → P3 → P4，每期可验收可回退，风险最低。

Q6 · UI 优化方向

✓ 移动端为主。P2 重写即按移动端优先重新设计：竖屏可用的牌桌、触控操作、系统断点；桌面端自适应增强。
